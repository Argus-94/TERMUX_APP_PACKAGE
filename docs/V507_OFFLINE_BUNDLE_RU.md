# AI Builder v507: локальная подготовка unsigned Karat package feed

Этот workflow — только source/build pipeline. При ручном запуске после отдельного review он собирает pinned Termux recipes, проверяет payload paths и dependency closure, выполняет изолированный локальный APT update/simulation и загружает короткоживущий Actions artifact только с локальными `feed/` и draft `manifest.json` (retention 1 день). Он не создаёт финальный package ZIP или подпись, не публикует Release/Pages, не меняет репозиторий, не использует ключи и не выпускает production claim. Сейчас package builds не запускались; никаких package artifacts этим изменением не созданы.

## Входы и происхождение

`termux-private-package-kit/v507/package-lock.json` фиксирует Termux source commit `505e06ef0c8dbd7611abfb90e9eb60826dcd01d7`, builder image `ghcr.io/termux/package-builder@sha256:44999857244619e25bc8e3427904a16d36cc0c0e087704af039e5bdf94814ac9`, точные recipe/patch hashes, application ID `com.karat.aibuilder` и целевой prefix `/data/data/com.karat.aibuilder/files/usr`. В локальной проверке SHA-256 bootstrap ZIP совпал с `08a447f60c06783f33561583553149cf992ac7d9779071c71b8aaeeb452451b4`; из него извлечён точный `var/lib/dpkg/status` с SHA-256 `5118bc12c7241bd457faae196bcd2c18ddb6b459505004669eee05bd2ec3262c`. Workflow повторно извлекает status и сравнивает с pin-файлом до dependency gate.

Build gate собирает ровно `ttf-dejavu`, `xorgproto`, `xorg-util-macros`, `termux-auth`, `openssh` и `perl` из pinned recipes (OpenSSH также выдаёт `openssh-sftp-server`). Base feed перед staging проверяется по исходным `Packages` Size/SHA256/metadata и полному payload audit. Старые base artifacts всех пересобираемых outputs исключаются и не переименовываются/не relabel-ятся как fresh builds; новые версии допустимы только после точной проверки package/version/architecture. Проверены точная recipe-resource applicability OpenSSH patch и применение Perl/termux-auth patches к источникам с recipe-pinned SHA-256. Любой payload path вне целевого prefix, строка с чужим Android app path или неверный symlink target блокирует pipeline. OpenSSH service runner должен использовать только подставляемый Karat prefix; literal `/data/data/com.termux` не допускается в payload.

## APT индекс и dependency gates

Индекс пересоздаётся через `dpkg-scanpackages -m`, чтобы сохранить несколько версий пакетов; проверяется точное соответствие индекса всем `.deb` в `pool/`. Создаётся только unsigned APT `dists/stable/Release` с SHA-256/size для `Packages` и `Packages.gz`; APT metadata остаётся unsigned. Custom closure checker проверяет `Pre-Depends`/`Depends`, alternatives, версии через `dpkg --compare-versions`, все package versions в feed и baseline package только при совпадении architecture/version. Неизвестный синтаксис и незакрытая relation блокируют gate. `dependencyClosureComplete` можно выставить только после успешного closure gate.

После создания draft manifest каждый файл feed сверяется с его Size/SHA-256. Только затем тестовый APT процесс использует единственный временный `file:` source с `trusted=yes`; конфигурация отключает source parts, использует скопированный bootstrap status и `APT::Architecture=aarch64`. Выполняются `apt-get update` и `--simulate --no-download --no-install-recommends --no-remove`; установка не выполняется, внешние APT sources не заданы. Это CI integrity/simulation gate, а не утверждение о готовности production APT trust. Feed не является «signed APT feed»: APT metadata не подписывается, и приложение может считать каталог доверенным только после проверки Karat manifest signature и SHA-256/размера каждого перечисленного файла.

## Unsigned handoff и границы

Draft manifest имеет состояние `catalogState: "build-gated-awaiting-karat-signature"`, `signatureAlgorithm: "SHA256withRSA"`, Karat certificate SHA-256 pin `b5dacc6f9c37adceace5c0d715eecb2762b5a0417468e221ec9c534ea1e6328e` и инвентарь каждого feed-файла с точными path/size/SHA-256. Подписи и APT/OpenPGP signature fields не создаются; production-qualified state не выставляется. Промежуточный artifact не является финальным или доверенным каталогом: отдельная локальная процедура должна проверить exact raw manifest bytes и каждый file hash, после чего локальный `/workspace/aibuilder-v506/tools/offline-bundle/KaratManifestSigner.java` подписывает manifest с JKS пользователя. Ключ и JKS не копируются в этот repository и не передаются в CI; пароли не записываются в workflow/logs.

Локально Docker недоступен, поэтому сборки и post-build payload/closure validation не выполнялись. Точный pinned source commit и три patch hunks проверены локально; Perl и termux-auth source archives совпали с recipe SHA-256. Bootstrap ZIP/hash/status подтверждены. Сейчас возможны только static tests и closure check базового feed; package artifacts, финальный workflow, artifact upload и production trust review остаются будущими шагами. Ни source compatibility после build, ни runtime compatibility не заявляются.
